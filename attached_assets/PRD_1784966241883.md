# Product Requirements Document — GroundCheck

**Hackathon:** HackSummer'26 — Theme: "Trust Me"
**Status:** MVP for hackathon submission

## 1. Problem

People have no reliable way to check whether a location-based claim is real — a "verified" business, a road hazard report, a property listing — before they act on it. Existing crowd-report tools (community flags, review sites) have two weaknesses: reports aren't checked against any independent ground truth, and the trust signal itself (votes, flags) can be manipulated with no one able to tell.

## 2. Goal

Give people a live map where every report of "is this real / is this safe / is this trustworthy" is:
1. **Cross-checked** against independent, real-world geographic data before it counts,
2. **Visualized** as a continuous trust surface rather than an isolated pin, and
3. **Protected** from manipulation by an auditable, tamper-evident record.

## 3. Target users

- Someone deciding whether to trust a location-based claim before acting on it (buying, visiting, reporting) — the primary user in the demo.
- A judge/reviewer evaluating whether the underlying trust signal can be gamed.

## 4. Core product experience

### 4.1 Mapbox map (foundation)
- Mapbox GL JS renders the interactive base map (dark theme), centered on the demo city.
- All interaction — pin placement, radius selection, heatmap rendering, popups — happens on this single Mapbox canvas. Mapbox is the surface every other feature is built on top of, not a separate view.

### 4.2 Radius-verified reporting
- User clicks a point on the Mapbox map to start a report.
- A radius control appears (50m–500m). As the user drags it, the app live-queries OpenStreetMap (Overpass API) for real-world features inside the current radius and shows a live "N matching features within Xm" readout directly on the map.
- User selects a category (fake business, road hazard, unsafe area, scam location), adds a short description, and submits.

### 4.3 Trust heatmap
- Each submitted report becomes a heat contribution on the same Mapbox map, not just a marker.
- The **radius chosen becomes the heat spread**, and the **confidence/trust score becomes the heat intensity/color** — a small, high-confidence report glows tight and green; a broad, low-confidence claim glows wide and faint red.
- As more reports land, the heatmap blends into a live trust surface across the map that updates in real time.

### 4.4 Security layer
- **Sybil / manipulation defense:** bursts of reports or votes from the same session in a short window are automatically down-weighted before they can influence the heatmap.
- **Impossible-travel check:** two reports from the same session claiming locations that couldn't physically be reached in the time between them are flagged and excluded pending review.
- **Tamper-evident audit chain:** every report is hashed (SHA-256) and chained to the previous one. A visible chain-integrity indicator sits alongside the map; a "Verify" action recomputes the chain and will visibly flag the map's trust surface as compromised if any record was altered.

## 5. User stories

- As a user, I can click anywhere on the Mapbox map and drop a report without leaving the map view.
- As a user, I can drag a radius control and see, live, whether real-world data supports my claim before I submit it.
- As a user, I can see at a glance — via the heatmap's color and spread — which parts of the map are trustworthy and which aren't, without reading individual reports.
- As a user, I can upvote or downvote a report and watch the trust score respond.
- As a judge/reviewer, I can click "Verify" and see cryptographic proof the report history hasn't been silently edited.

## 6. Success metrics (for the demo)

- A report near a real, matching OSM feature visibly scores higher and produces a tighter, greener heat glow than one placed where nothing matches.
- The heatmap visibly updates in real time as reports are added.
- The chain-verify action visibly passes on an untouched chain and visibly fails when a record is tampered with.
- Manipulated/spoofed submissions are visibly excluded or down-weighted rather than silently accepted.

## 7. Scope

**In scope (MVP):**
- Mapbox GL map, click-to-report, live radius-scoped OSM check, heatmap rendering keyed to radius + score, upvote/downvote, SHA-256 hash chain + verify action, basic sybil/impossible-travel flagging.

**Out of scope (MVP):**
- User accounts / persistent identity beyond a session ID.
- Cross-session data persistence (in-memory for the demo).
- Real land-registry or government data integration (OSM only for MVP).
- Mobile-native app (responsive web only).

## 8. Rubric alignment

| Rubric criterion | How this product addresses it |
|---|---|
| Theme relevance | Every feature exists to answer "can this be trusted" |
| Innovation | Radius-as-heat-spread and score-as-heat-intensity is a novel, single visual language tying verification directly to the map |
| Execution/demo | Live, clickable, visibly reactive on the Mapbox map |
| Technical depth | Geospatial querying, scoring, cryptographic chaining, anomaly detection |
| Feasibility | Built on free, real data (OSM) and a standard mapping platform (Mapbox); extensible to authoritative data sources post-hackathon |
