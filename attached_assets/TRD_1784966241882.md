# Technical Requirements Document — GroundCheck

**Companion to:** PRD — GroundCheck
**Deployment target:** Replit (static/Node), Mapbox GL JS

## 1. Architecture overview

Single-page web app. The Mapbox GL map instance is the central object — the radius control, heatmap layer, markers, and popups are all layers/controls attached to it, not separate views.

```
Browser
 ├─ Mapbox GL JS map (base layer, dark style)
 │   ├─ Marker layer (per-report pins)
 │   ├─ Heatmap layer (Mapbox heatmap layer, weighted by trust score, radius by report radius)
 │   └─ Popup (score breakdown per report)
 ├─ Radius control (HTML slider bound to map click state)
 ├─ Scoring engine (client-side JS)
 ├─ Security module (sybil / impossible-travel checks, client-side for MVP)
 ├─ Hash-chain module (Web Crypto SHA-256)
 └─ Overpass client (fetch to overpass-api.de)
```

No backend server required for the MVP — all state lives in-memory in the browser session. This keeps the Replit deployment trivial (static HTML/JS/CSS) while still meeting the "must use Replit" requirement via Replit's hosting/deployment.

## 2. Mapbox integration (core surface)

- **Library:** Mapbox GL JS v3.x, loaded via CDN.
- **Style:** `mapbox://styles/mapbox/dark-v11` (matches the trust/security visual tone).
- **Auth:** Mapbox public access token (`pk.*`), free tier, entered once at load time.
- **Base interaction:** `map.on('click', ...)` captures the pending report location; `NavigationControl` added for zoom/pan.
- **Report markers:** `mapboxgl.Marker`, color-coded by computed trust score at render time and on every score update (vote change).
- **Heatmap layer:** implemented as a Mapbox GL `heatmap` layer on a GeoJSON source. Each report is a GeoJSON point feature with properties `{ weight: trustScore, radius: reportRadiusMeters }`. The layer's `heatmap-weight` and `heatmap-radius` paint properties are expressions keyed to these properties, so the radius chosen at submission time and the computed trust score directly drive the rendered glow — no separate heat model outside Mapbox's own layer.
- **Popups:** `mapboxgl.Popup` bound to each marker, rendering the score breakdown (OSM match points, community points, baseline) and the report's chain hash prefix.

## 3. Radius-verified reporting flow

1. `map.on('click')` sets `pendingLatLng` and reveals the radius slider + category/description form.
2. On `input` of the radius slider, the client re-issues an Overpass query scoped to the current radius (debounced ~300ms to avoid hammering the public API) and updates a live "N features within Xm" readout.
3. On submit, the final radius and Overpass result are locked into the report object.

### Overpass query shape
```
[out:json][timeout:10];
(
  node(around:<radius>,<lat>,<lon>)[<category-tag-filter>];
  way(around:<radius>,<lat>,<lon>)[<category-tag-filter>];
);
out center 10;
```
Category-tag filters map report category → OSM tags (e.g. fraud/scam → `shop`, `amenity`; hazard → `highway`). No API key required; public Overpass instance (`overpass-api.de`).

## 4. Trust scoring engine

```
score = osmPoints (0-40) + communityPoints (0-40) + basePoints (0-20)
```
- `osmPoints`: distance-banded — nearest matching OSM feature ≤25m → 40; matched but farther → 25; no Overpass reachability → neutral 12; no match found → 5.
- `communityPoints`: `clamp(0, 40, 20 + (upvotes - downvotes) * 4)`, but votes are first passed through the security module (§5) — manipulated votes are down-weighted before this calculation.
- `basePoints`: fixed MVP baseline (20); reserved for future reporter-reputation integration.

Score maps to heatmap weight directly and to marker color via three bands: ≥70 high (green), 40–69 mid (amber), <40 low (red).

## 5. Security module

### 5.1 Sybil / vote-manipulation defense
- Each session (`session id`, generated client-side per load) has its actions timestamped.
- If more than N actions (reports or votes) occur from one session within a short rolling window (e.g. 5 actions / 30s), subsequent actions in that window are down-weighted (reduced contribution to `communityPoints`) rather than rejected outright, to avoid false positives from legitimate rapid use during a demo.

### 5.2 Impossible-travel check
- For each session, compare the location and timestamp of consecutive reports.
- Compute required travel speed = distance / time delta. If it exceeds a plausible threshold (e.g. >200 km/h, generously above any ground transport), flag the later report as `spoof_suspected` and exclude it from heatmap/score contribution until manually reviewed (UI shows a distinct "unverified — flagged" marker state).

### 5.3 Tamper-evident hash chain
- Every report, on creation, is hashed via `crypto.subtle.digest('SHA-256', ...)` over `previousHash + JSON(reportCoreFields)` and appended to an in-memory chain array `{ id, prevHash, hash }`.
- **Verify action:** recomputes the chain from report 0 forward; any mismatch between recomputed and stored hash identifies the exact broken link and surfaces it in the UI (chain status indicator + optional heatmap dim/hazard overlay).
- This protects the integrity of the *record*, distinct from §5.1/5.2 which protect the integrity of the *inputs* — together they cover both "was this data faked" and "was this data altered after the fact."

## 6. Data model (in-memory)

```
Report {
  id: uuid
  category: enum(fraud|hazard|unsafe|scam)
  desc: string
  lat, lon: float
  radiusMeters: number
  time: epoch ms
  session: string
  up, down: int
  osm: { matched: bool|null, nearestM: number|null, count: int }
  flagged: bool            // set by impossible-travel check
}

ChainLink { id, prevHash, hash }
```

## 7. Non-functional requirements

- Overpass calls debounced and capped to avoid public-API rate limiting during judging.
- Map must remain responsive (<200ms interaction feedback) while a query is in flight — loading state on the radius readout, not a blocking UI.
- Must run from a static Replit deployment with no server-side secrets beyond the Mapbox public token (which is safe to expose client-side by design).

## 8. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Overpass API slow/unavailable during live demo | Neutral (non-zero, non-damning) score fallback already defined in §4; pre-test demo locations beforehand |
| Sparse OSM coverage in demo area gives false "no match" | Frame explicitly in the pitch as a known signal-confidence limitation, not a false negative |
| Public Mapbox token exposed client-side | Expected/standard for Mapbox public tokens; scope token to URL restrictions in production |
| In-memory-only state lost on refresh | Acceptable for hackathon MVP; flagged as first post-hackathon addition (Replit DB or Supabase) |
